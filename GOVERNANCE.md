# Governance and maintenance

Robert Leggieri is the initial maintainer and decision owner. Routine fixes use pull-request review
and automated checks. Changes to scientific claims, required evidence, default calibration,
grouping, resampling, or candidate-selection behavior require:

1. an issue stating the proposed change and failure mode;
2. adversarial tests;
3. documentation of evidence implications; and
4. an explicit maintainer decision before merge.

Releases use semantic versioning, with alpha versions while APIs and evidence demonstrations are
incubating. If maintenance becomes unsustainable, the repository will be marked archived or a new
maintainer will be named transparently; stewardship will not be transferred silently.
